## Project-specific additions

### Deviation from core R2/R3: `docs/` is canonical for consumer-visible behaviour

Core R2/R3 give the agent tree the depth and the human tree a summary. php-qa-ci reverses that
for one class of fact. Anything a consumer can observe (a lane's behaviour, a rule's correct
construction, configuration, the pipeline's order and preparation) is canonical in `docs/`:
`docs/tools/`, `docs/phpstan-rules/` and the consumer-behaviour pages such as
`docs/pipeline.md`, `docs/configuration.md` and `docs/platform-detection.md`. `CLAUDE/` owns
agent-only material: architecture and its invariants, contributor procedures and Owner rulings.

Why: Defence Before Fix requires an offline page per stable identifier, `rule-doc` resolves
every identifier into `docs/`, and those pages ship to every consumer. Moving the depth into
`CLAUDE/` would leave the shipped pages as summaries of a tree a consumer's agent never reads.

The daemon-owned `.claude/rules/human-docs.md` still advises "point into the agent tree" on a
`docs/` edit. The project rule `.claude/rules/phpqaci-reference-docs.md` states this exception at
the point of use and links here.

### The binding floor in root `CLAUDE.md` (R4a)

Root `CLAUDE.md` restates every Owner ruling as a short bullet ending in a link to its canon.
The R4a marker is one **block-level** comment on its own line before the list:

`<!-- binding-floor: each bullet cites its canon -->`

Never a per-bullet comment inside a list item: Claude Code strips only block-level comments
before injection, and the markdown formatter can fold an in-list comment into the item. A bullet
that is itself the canon (the knowledge & memory policy) says "canonical here" and is not an R4a
restatement.

### Nested `CLAUDE.md` versus path rules

One trigger mechanism per subtree. A directory-shaped trigger that matters when php-qa-ci is
worked on from a consumer's `vendor/lts/php-qa-ci/` gets an R7d routing-table `CLAUDE.md` (at most
15 lines, pointers only): `src/Pipeline/`, `src/PHPStan/`, `scripts/`. Nested `CLAUDE.md` files
load lazily from a vendored checkout too; `.claude/rules/` are expected not to. A file-shaped or
cross-cutting trigger gets a `phpqaci-*` path rule (R7a), which is an accelerator only: every
pointer it carries is also reachable from the root navigation map. No `CLAUDE.md` goes under
`docs/`, which ships and which `docsProse` and `markdownLinks` scan.

### The active-defences region and R10

The `phpqaci-active-defences` region of root `CLAUDE.md` is generated by
`php bin/rules . --write-agent-summary=CLAUDE.md`. `documentation.qa.generated_docs` takes a
whole-file `glob` plus a `generator`, and cannot declare a region: declaring `CLAUDE.md` would
mark every hand edit of the floor as a hand-edit of a generated file. The region therefore stays
undeclared, and the R10 advisory is accepted. `AgentContextIsCurrentTest` is what keeps the
region byte-identical to its generator.
