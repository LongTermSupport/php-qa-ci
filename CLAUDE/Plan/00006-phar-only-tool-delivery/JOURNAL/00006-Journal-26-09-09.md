## 23:27 · decision · T1.2 — PHIVE, not a hand-rolled manifest

The plan text called for a sha256 manifest under `build/` plus a fetch script for the unsigned
parallel-lint release asset. Started building exactly that, then the Owner asked whether that was
reinventing PHIVE. It was: PHIVE 0.16 installs github `owner/project` release assets and has
`--force-accept-unsigned`. `phive install --copy --force-accept-unsigned
php-parallel-lint/php-parallel-lint@^1.4` produced byte-identical output (sha256
`7f584ddcb39e36ea491b3fbca133abeb623c1a26d90ef44c494379025c233ce5`) to the release asset.
Manifest and script deleted; `phive.xml` carries the entry, `tool-install.bash` passes
`--force-accept-unsigned`, `PharToolsVerifier` needs no change. PLAN.md Task 1.2 reworded.

Caveat for Task 3.2: `phive update` has no unsigned flag, so `update-deps.yml` must call
`scripts/tool-install.bash update` (rm + install) rather than `phive update` directly.
