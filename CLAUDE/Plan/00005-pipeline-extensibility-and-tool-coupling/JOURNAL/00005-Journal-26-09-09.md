## 15:44 · decision · joseph — P1 — the two in-flight changes were feature-branched, not shipped

The Owner needed `php8.5` released so client projects can start consuming it, and separately
raised two design corrections mid-flight. Rather than hold the release for them, the release
went out at `085f595` and the corrections went to
`feature/twig-decoupling-and-variadic-narrowing`.

Both were the Owner's call and both are right:

**"we simply should not be suggesting variadic for anything with optional params"** — the rule
already skipped a parameter followed by an optional one, on the "unpacking after named
arguments" fatal. It did not skip a parameter carrying its OWN default, on the reasoning that a
variadic is inherently optional so nothing is lost. That holds only for an empty default: PHP
has no syntax for `string ...$items = ['a']`, so converting `f(array $items = ['a'])` silently
drops it. The exclusion now starts at the parameter itself.

**"the twig lint is not coupled to Symfony, it's coupled to Twig"** — right, and the two twig
lanes are not the same case. `TwigLintTool` shells out to `bin/console lint:twig`, so it IS
Symfony-coupled and stays a platform lane. `TwigCsFixerTool` runs a standalone PHAR with no
framework involvement, so gating it on `symfony.lock` meant a Slim, Laravel or plain library
project using Twig got no Twig coding standards at all.

Two things fell out of that second one that the original review missed:

- The gate was only half the coupling. `twigDirectories` defaulted to `[]` off Symfony, so a
  generic Twig project would have skipped anyway even after the gate changed. `templates/` is
  now the default on every platform, which is safe because the lane drops directories that do
  not exist.
- The lane's own read-only guidance has been telling users to run `vendor/bin/qa -t twigcs`
  since it was written, and that alias did not exist — platform lanes are not `-t` selectable.
  Moving it into the shipped registry fixes a latent defect nobody had hit yet.

Both commits are unit-green (840 tests) and `allStatic`-green, but neither has had a full
battery. That is not a formality: both changed the shape of code the mutation run scores.

`thisOrAnyLaterParamIsOptional` lost its `$index + 1` literal (the loop now starts at `$index`),
and the `twigDirectories` default lost its ternary. Both REMOVE mutants, which should help. But
`0973cc6` also added a registry row, a new lane guard and a new default, which ADD mutants — and
the previous release finished at exactly 82% against an 82% floor, with no headroom at all.

The floor is Owner-only. If it is missed, the fix is assertions on the new behaviour, never a
lower floor.
