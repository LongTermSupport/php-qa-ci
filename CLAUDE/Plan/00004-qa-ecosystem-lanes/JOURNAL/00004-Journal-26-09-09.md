## 09:20 · finding · — — DBF 3.1 record: inconsistently documented promoted properties

**Class**: a constructor whose promoted properties are documented some-but-not-all.
**Hazard**: a reader cannot tell whether an undocumented member is self-explanatory or
forgotten, and the documented ones invite comments that restate the name; the mixed state
is what makes both the sloppy comment and the missing one invisible in review.

**Instance**: `QaConfigDto::$useComposerAudit` given a comment while its neighbours had none
(reverted by hand before this record; the class still has 7 of 23 documented).

**Two independent search techniques, chosen before the rule existed**:

1. AST walk (`untracked/scratch/dbf-search.php`, nikic parser, code independent of the
   rule): every `__construct` with two or more promoted params, counting those with a doc
   comment. Found **13** constructors in `src/` and `tests/`: JustificationFindingDto,
   RunRequestDto, InfectionOptionsDto, ProjectPathsDto, QaConfigDto, BranchPolicyConfigDto,
   BranchVerdictDto, LockInfoDto, ProcessResultDto, ProcessSpecDto, ToolDefinitionDto,
   ToolResultDto, ToolContext.
2. Text search: `grep -B1` for a `/** ... */` line directly above a promoted parameter,
   counted per file against the promoted-parameter count per constructor. Found the same
   13 plus files where every promoted param is documented (PhpUnitOptionsDto,
   Psr4Validator, FakeProcessRunner, ToolRegistry), which are not instances. Nothing the
   AST walk missed; saturated.

**Bounds**: constructors with fewer than two promoted properties cannot be inconsistent and
are excluded. Next wider rule: non-promoted constructor parameters documented
some-but-not-all via `@param`. Not built: those share one docblock, PHPStan's own
`missingType.*` checks report a partial `@param` list where a type is involved, and the
search found no mixed case.

**Runner check**: none. Coding-standard class with no runtime behaviour to assert; the
rule is the whole defence.

## 09:25 · finding · — — DBF 3.1 record: repeated string literal within one class

**Class**: the same string literal written three or more times inside one class instead of
being defined once as a constant.
**Hazard**: the value has no single definition, so an edit to one occurrence leaves stale
siblings, and the reader cannot tell what the value means or whether two occurrences are
meant to be equal.

**Instance**: `'8.5.10'` written 20 times across `ComposerChecksToolTest`.

**Two independent search techniques, chosen before the rule existed**:

1. AST walk (same scratch script): per class, every `String_` that is not an attribute
   argument, an array key or an array-dimension index, of length three or more and not
   whitespace-only; reported at three or more occurrences. Found **197** (16 in `src/`,
   181 in `tests/`, `tests/assets` fixtures excluded).
2. Text search: per file, `grep -o "'[^']{3,}'" | sort | uniq -c` at three or more. Found
   200 lines over 89 files; the difference is the grep counting array keys and attribute
   arguments and seeing single-quoted strings only. Every AST instance appeared in the grep
   set; the grep found no excluded value that carries the hazard.

**Bounds** (each exclusion with its sentence):
- Array keys and array-dimension indexes: the repeated key is how an array shape is
  spelled, and PHPStan's array-shape typing reports a misspelt key where the shape is
  typed; a constant per key would obscure the shape.
- Attribute arguments: declarative metadata read by tooling, not values the class
  computes with.
- Fewer than three characters, or whitespace-only: too short to carry meaning that could
  drift.
- Fewer than three occurrences: two is as often coincidence as identity.
- A nested class-like is counted by its own InClassNode.

Next wider rule: the same literal repeated across classes in one namespace. Not built: a
cross-class constant is a design decision (which class owns it) and PHPStan analyses one
file at a time; the search found no cross-class repetition that a single-class rule leaves
unaddressed inside any one class.

**Runner check**: none; coding-standard class, the rule is the defence.

**Sweep decision**: all first-party source (`src/`, `tests/` excluding `tests/assets`
fixtures, `qaConfig/`); `vendor/` and `vendor-phar/` excluded as third-party.

## 09:50 · decision · — — the docs class widened, then bounded to declarations

Owner review of the promoted-property rule: the class is consistent documentation in
general, not promoted properties. Re-measured with the AST technique over three member
kinds, "documented" meaning a docblock with free text (tag-only docblocks are type
metadata):

| kind | mixed classes |
| --- | --- |
| constants (class constants + enum cases) | 10 |
| properties (declared + promoted) | 15 |
| methods (excluding `__construct`) | 58 |

Methods are excluded from the class, with this narrowing sentence: a method's docblock
explains a body the reader can read, whereas a declaration has only its name and type, so
a comment there is the only place meaning beyond the name can live, and that is where mixed
coverage misleads. Forcing all-or-none over methods would either strip the one genuinely
needed explanation in a class of eleven methods or manufacture ten comments that restate
names; the Owner's direction is that the fix must be able to remove bloat, never to create
it. Class as built: `RequireConsistentMemberDocsRule`, `phpqaci.consistentMemberDocs`,
per-kind over constants and properties. Instance count from the search: 25.
