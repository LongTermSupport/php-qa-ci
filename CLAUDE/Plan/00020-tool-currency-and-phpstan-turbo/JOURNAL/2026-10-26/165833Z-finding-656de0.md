## 16:58 · finding · —   — Update workflow failures, fixed in 85.9.1 to 85.10.0

The scheduled dependency update failed twice in a row and was repaired in two releases: PHPStan 2.3.2 changed the wording of its diagnose output for the Turbo extension (the Turbo status check read it as not running; fixed in 85.9.1), and Rector 2.8 removed `RectorConfig::cacheClass()`, which the three shipped Rector configs called (fixed in 85.9.2). The update then went green and its pull request needed tests for 29 mutants in two re-quoted source files before the Infection floor held (released as 85.10.0).

Two lessons for tool currency. First, the update workflow is the only place a candidate tool version meets the shipped configs: nothing checks a candidate phar against them before the update run, which is the gap that let the Rector break surface only there. Second, any change to files that Infection reads as configuration forces a full mutation run that does not fit the job limit (tracked as #344), so updates touching those files cannot land through a normal pull request.
