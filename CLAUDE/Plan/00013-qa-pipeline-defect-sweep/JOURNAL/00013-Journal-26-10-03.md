## 10:40 · decision · T3.1 — a rule is named by its because clause

PHPArkitect exposes no rule name except the `because` text, and Plan 00010 Decision 5
rules out parsing its prose into identifiers. The harness matches the clause as text
against the violation messages, which the lane already reads as JSON. No identifier is
invented, so the public-API question the sizing note raised does not arise.

## 10:45 · finding · T3.1 — the project entry config hard-codes its class set

The template builds `ClassSet::fromDir(__DIR__ . '/../src')`, so redirecting
`PHPQACI_ARKITECT_SRC_DIR` cannot point a project's rules at a fixture. The probe
instead loads the entry config into a scratch `Config` and re-adds every registered rule
against the probed directory, using only arkitect's public `getClassSetRules()` and
`getRules()`.

`/bin/*` is ignored, and each shipped entry is re-included by name.
`bin/arkitect-rule` was declared and present, and `ComposerBinManifestTest` passed, but
git would never have tracked the file. The detector went in first (f6e4789, red), and
the `.gitignore` re-include followed in 38961c0.

## 11:40 · decision · T3.1 — no lane or `-t` token for fixtures

The fixture's permanence is the project's PHPUnit test running the command; the

## 12:20 · finding · T3.3 — six scanning lanes drop withIgnoredPaths()

Worked in a separate worktree off `bugfix/known-defects-sweep`; its clock read 11:00 to
11:40 for this work, so these entries carry times after the last one rather than that
clock. Two techniques: a text search for `pathsToIgnore` over `src/` (five consumers:

detector, `IgnoredPathsReachEveryScanningLaneTest`, went in red first (292d3c0).

## 12:25 · decision · T3.3 — analyse, optional, absolute

The PHPStan exclusion is `excludePaths.analyse`: analysed code may reference a class
under an ignored path and must still discover it. Each entry carries `(?)` because
PHPStan refuses a required entry that exists nowhere (`ValidateExcludePathsExtension`),
and this repository's own `src/PHPUnit/TestDox` ignore is exactly that. The phar
normalises a plain-list `excludePaths` per file before merging, so the block combines
with any project list.

## 12:30 · decision · T3.3 — PHP CS Fixer through a generated config

`--path-mode=intersection` only narrows the config's finder (read in the phar's
`ConfigurationResolver::resolveFinder()`), so the exclusion has to be in the finder. A
generated `var/qa/phpCsFixer/php_cs.php` wraps whatever config resolves, which survives a
copied `php_cs.php` or finder; editing the shipped files would not. On this repository
`list-files` yields 137 `tests/assets` files through the plain config and none through
the wrapper.

## 12:35 · finding · T3.3 — Rector's Safe conversion broke a realpath fallback

Rector turned `realpath()` into `\Safe\realpath()`, which throws where the original
returned false, and the fixer lane then crashed on the stale `src/PHPUnit/TestDox`
ignore. Both call sites now check `file_exists()` first, and the psr4 test ignores a path
that does not exist.
