## 10:40 · decision · T3.1 — a rule is named by its because clause

PHPArkitect exposes no rule name except the `because` text, and Plan 00010 Decision 5
rules out parsing its prose into identifiers. The harness matches the clause as text
against the violation messages, which the lane already reads as JSON. No identifier is
invented, so the public-API question the sizing note raised does not arise.

## 10:45 · finding · T3.1 — the project entry config hard-codes its class set

The template builds `ClassSet::fromDir(__DIR__ . '/../src')`, so redirecting
`PHPQACI_ARKITECT_SRC_DIR` cannot point a project's rules at a fixture. The probe
instead loads the entry config into a scratch `Config` and re-adds every registered rule
against the probed directory, using only arkitect's public `getClassSetRules()` and
`getRules()`.

## 11:20 · finding · T3.1 — a declared bin can be silently gitignored

`/bin/*` is ignored, and each shipped entry is re-included by name.
`bin/arkitect-rule` was declared and present, and `ComposerBinManifestTest` passed, but
git would never have tracked the file. The detector went in first (f6e4789, red), and
the `.gitignore` re-include followed in 38961c0.

## 11:40 · decision · T3.1 — no lane or `-t` token for fixtures

The fixture's permanence is the project's PHPUnit test running the command; the
`phpunit` lane already runs it. A lane would need a fixture-to-rule registry format,
which is new public API, and is left to the Owner.

## 12:00 · finding · T3.2 — no daemon handler can carry the rule

Neither the installed daemon (3.63.0) nor upstream v3.67.0 has a handler that takes
arbitrary command patterns. php-qa-ci ships no daemon project handlers, so shipping one
would open a new Python deploy channel. The upstream issue text is drafted in
`subagent-reports/261003-plan-00013-followons-opus.md`.
