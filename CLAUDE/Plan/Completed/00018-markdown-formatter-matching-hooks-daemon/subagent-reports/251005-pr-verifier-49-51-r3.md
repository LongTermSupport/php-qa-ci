### 5. Does the lexical folding introduce anything new?

Folding itself (`phparkitect-class-set.php:42-64`), checked against the table and by reading:

- `.`, empty segments and a trailing slash are dropped; `..` pops; `..` past `/` is dropped on an
  absolute path (as `realpath()` would); a leading `..` on a relative path is kept (`'..' !== end()`
  guard), so `../../x` folds correctly. An ignored path given with `..` is folded and matches.
- No symlink is resolved, matching Finder's pathnames (it follows links but keeps the link name)
  and matching every other lane, which compares the literal `IgnoredPaths::$absolute`.

Shapes that regress against the round-2 head `e808b66` (but not against `2c59bd0` or `php8.5`):

- **A symlinked project root on one side only.** Not reachable through the pipeline:
  `bin/bootstrap.php:47` takes `realpath()` of the autoloader, `bin/qa:18` derives `projectRoot`
  from it, so `IgnoredPaths::$absolute` (`src/Pipeline/Config/IgnoredPaths.php:25-37`) and the lane's
  `srcDir` are already symlink-free; and PHP's `__DIR__` in the template is the resolved path. So
  both sides are real paths in every pipeline route. Before #49, `php8.5`'s arkitect lane did not
  honour ignored paths at all, so #49 makes nothing worse than the base. `e808b66` handled it,
  `2c59bd0` did not; it is unreachable in practice either way.
- **A relative srcDir** (`(require getenv('PHPQACI_ARKITECT_CLASS_SET'))('src')` in a project's own
  entry config). The folded `src` never prefixes the absolute ignored paths, so nothing is
  dropped. No shipped config or doc passes a relative path: the template, the default entry config
  (`getenv('PHPQACI_ARKITECT_SRC_DIR') ?: getcwd() . '/src'`), the CHANGELOG example and the factory's
  docblock all pass an absolute one. Not a documented route, so **non-blocking (N4 below)**. It
  is cheap to close (prefix `getcwd()` to a relative path inside `$canonical`) and would make the
  factory accept every shape `e808b66` accepted.

Nothing else new found.

### 6. The empty-object restoration (`IgnoredPathsInfectionConfig.php:118-149`)

- It can only ever replace a value that is exactly `[]` and whose counterpart in the
  object-decoded original is a `stdClass`. Any other value is returned unchanged or recursed into
  key by key, and keys that `derive()` added (absent from the original) are not visited. So no
  non-empty value can change. Reproduced by the structural comparison in 3.
- A list that `derive()` empties (every source directory ignored) has an array, not an object, as
  its counterpart, so it stays `[]`; the lane skips that case anyway (`InfectionTool.php:150`).
- Output validates against Infection's schema (3).
- Observation, not a finding: an object whose keys are exactly `"0"`, `"1"`, … decodes to a list
  and is re-encoded as a JSON array (reproduced with `PublicVisibility: {"0": "x"}`). No
  schema-valid Infection config has such an object, so I do not raise it.

### Issue #54 (ProcessTreeTest flake): classification

**Agree: pre-existing, unrelated to #49.**

- `git diff origin/php8.5 0405f50 -- tests/Large/Pipeline/Process/ProcessTreeTest.php src/Pipeline/Process/ProcessTree.php`
  is empty; `symfony/process` is the same version (v8.1.7) on both.
- Mechanism confirmed by reading: the test (`ProcessTreeTest.php:103-106`) starts `true` and then
  calls `getPid()`, which in Symfony Process v8.1.7 is `$this->isRunning() ? pid : null`
  (`vendor/symfony/process/Process.php:557-560`); `isRunning()` goes through `proc_get_status()`,
  which reaps an already-exited child. A fast `true` is therefore reaped (or `getPid()` returns
  null, cast to 0) before the zombie wait, so the test's precondition is racy.
- Reproduced: run alone 20 times at `0405f50` on this (loaded) host, it failed **7 of 20**, every
  time with `nothing has reaped it yet, so it is a zombie`. The rate is higher than the issue's
  2/20, consistent with host load; the classification and fix direction in #54 stand.
