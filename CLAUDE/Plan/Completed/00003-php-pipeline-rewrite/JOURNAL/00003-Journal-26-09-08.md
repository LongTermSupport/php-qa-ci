> **Append-only activity log** for plan 00003. One file per day
> (`00003-Journal-YY-MM-DD.md`). `PLAN.md` tracks the plan (what/why,
> current state, tasks); this journal tracks what actually *happened* —
> findings, decisions, dead-ends, hand-off state — the linear lifecycle a plan
> document structurally cannot carry.
>
> **Entry grammar** — append new entries at the BOTTOM; NEVER edit earlier
> entries (corrections are new entries):
>
> ```
> ## HH:MM · category · REF   — optional short title
> ```
>
> - `HH:MM` local 24h (the date is in the filename); times increase down the file.
> - `category` ∈ `action` | `finding` | `decision` | `thought` | `blocker` | `handoff`
> - `REF` = optional task/phase ref (`T1.2`, `P1`) or `—`.
> - Bodies may embed fenced logs/diffs/snippets — no size limit — with a
>   one-line takeaway above the fence.
> - End a working session with a `handoff` entry so the next agent's entry
>   point is the last entry of the newest day-file.

## 22:40 · action · P1 — foundations landed

Config, Tool, Process and Lock namespaces written test-first (196 Small tests, PHPStan max
clean). Two rule-driven design choices worth knowing:

- `QaConfigBuilder` is `final readonly` with withers, not a mutable builder: the opt-in
  `RequireReadonlyServiceRule` (enabled in this repo's self-check) flags any `final` non-readonly
  class that is not in its exception list, and "Builder" is not. A consumer's `qaConfig/qa.php`
  therefore returns the adjusted builder rather than mutating one.
- DTOs live under a `Dto\` segment with a `*Dto` suffix (arkitect default tier), so
  `ProjectPathsDto`, `QaConfigDto`, `ToolDefinitionDto`, `ToolResultDto`, `ProcessSpecDto`,
  `ProcessResultDto`, `LockInfoDto`.

The comment-size guard misreads a `'/*'` glob literal in PHP as an opening comment; tests use
`TempDir` (tests/Support) and `scandir` instead of `glob($dir . '/*')`.
