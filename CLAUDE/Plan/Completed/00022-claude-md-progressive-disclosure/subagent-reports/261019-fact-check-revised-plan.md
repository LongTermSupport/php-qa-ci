## REFUTED claims, most consequential first

### R-A. FLOOR-CLAUSES.md F13: the canon does not hold the "not `CI=true`" half (partial)

- The claim: the Canon column names `CLAUDE/prepush-verification.md` for "reproduce a CI failure with `QA_READONLY=1`, not `CI=true`".
- The canon says `QA_READONLY=1` "has exactly one use: reproducing a CI failure" (`CLAUDE/prepush-verification.md:26`).
- Nothing in `CLAUDE/`, `docs/` or `README.md` says `CI=true` does not make a run read-only. `git grep` for orthogonal, "does not make" and "not CI=true" outside `CLAUDE.md` and the plan returns nothing.
- `CLAUDE/prepush-verification.md:45` even shows `QA_READONLY=1 CI=true bin/qa`.
- That fact (CI = interactivity only, read-only is orthogonal, `CLAUDE.md` Read-Only section) exists only in `CLAUDE.md`.
- Change to the plan: Task 3.5 must add this sentence to `CLAUDE/prepush-verification.md` (or `docs/configuration.md`) in the commit that removes the Read-Only section, and F13 must not claim the canon already carries it.

### R-B. PLAN.md Overview: "five Owner rulings exist only here" (partial)

- The release-line ruling is restated in `README.md:518-525`: php8.5 is the default branch, php8.4 takes a fix when a project reports the bug, php8.3 is unmaintained, "say which line you are on". It is also in `.github/ISSUE_TEMPLATE/bug_report.yml:9`.
- The memory ruling is stated in `.claude/hooks-daemon.yaml:3-8`.
- The exception for #36, "not backported proactively", the issue-states-its-line trigger and the "Owner decision" framing are unique to `CLAUDE.md`.
- Change to the plan: say "the canonical text of five Owner rulings exists only here". Add `README.md#branches-and-versions`, the issue form and `hooks-daemon.yaml` to the per-fact check for Decision 3 and Task 3.3, and let `CLAUDE/release-lines.md` link README rather than restate it (Decision 2).

### R-C. DECISIONS.md Decision 4: "unlike php-qa-ci's `.claude/skills` it also works when dogfooding"

- The plan's own source contradicts this. Mechanics report item 16 says "Nested `.claude/skills/` load the first time a file in that subdirectory is touched". A vendored `vendor/lts/php-qa-ci/.claude/skills/` would then load on a touch, as `CLAUDE.md` does.
- The report says nothing either way about nested `.claude/rules`, which is the claim Task 1.2 (b) tests.
- Change to the plan: drop the comparison, or add a Task 1.2 (b) sub-test "a skill under the vendored `.claude/skills` is offered after a vendored file is touched". The "no new skills" conclusion still holds on the resident-description cost.

### R-D. PLAN.md Task 6.6 and the inventory: "mdformat column padding inflates the injected rules table (about 83.7k chars raw)"

- 83,664 chars is the whole "All other enforced rules" section, `CLAUDE.md:1096-1378` (heading, table and blank lines).
- The 132 table rows alone are 80,520 chars.
- Change to the plan: say "the rules section (about 83.7k chars raw; the table rows 80.5k)". Cosmetic, but this sentence goes into an upstream issue.

### R-E. FLOOR-CLAUSES.md F03, "a `bin/rules` entry" (minor)

- `CLAUDE/tool-boundaries.md:14-18` names the identifier, `rule-doc`, the identifier index `docs/phpstan-rules/README.md` and the docs page. It does not say "a `bin/rules` entry".
- That wording is in `CLAUDE.md:35-36`, and the entry is generated.
- Change to the plan: either add the clause to the canon or reword F03 to "indexed in `docs/phpstan-rules/README.md`".
