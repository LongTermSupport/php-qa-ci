## 08:45 · finding · T3.2 — why not `composer require`

`shipmonk/dead-code-detector` declares `extra.phpstan.includes`, so the extension installer
registers it in whichever project installs it. Required by php-qa-ci it would be always-on in
every consumer's gate, and the root-only `extension-installer.ignore` cannot be set for them. So:
`build/dead-code-detector/` manifest, `scripts/build-phar.bash dead-code-detector`, and the lane
includes `phar://.../rules.neon` from the PHAR. First attempt loaded the classes through
`bootstrapFiles`, which failed with "Class ... RemoveDeadCodeFormatter not found": bootstrap
files run after the container is compiled, and the spike had only worked because the package was
still in vendor at the time. `--autoload-file phar://.../vendor/autoload.php` loads before the
container and works (also via a plain PHP shim; the direct path is used).
